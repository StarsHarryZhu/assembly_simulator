# 汇编模拟器（Assembly Simulator）

[English](README.md) ｜ **中文**

在浏览器里写、汇编、单步运行汇编的教学工具，支持两种架构：

- **MIPS32**：指令集和行为对齐 **MARS 4.5**。
- **ARMv9-A（AArch64）**：GNU as 语法，按 Linux 进程运行：A64 基础指令、浮点、Neon、SVE/SVE2、SME/SME2，带 Linux 系统调用和内置的 C 库。

引擎是我们自己写的，网页里不包含任何 MARS、LLVM 或 QEMU 的代码。构建结果是一个独立的 `index.html`，放到 GitHub Pages 上能用，下载到本地双击也能用，不需要联网。

在线使用：<https://starsharryzhu.github.io/assembly_simulator/>（源码在 [GitHub](https://github.com/StarsHarryZhu/assembly_simulator)，以 [MIT](LICENSE) 许可证开源）。

界面支持**中文和英文**：第一次打开时跟随系统语言（不是中文也不是英文时用英文），之后可以在右上角切换，会记住你的选择。也可以切换浅色和深色主题。左上角选择架构，每种架构的代码和设置分开保存。

## 三个栏目

### 编辑运行

- **编辑器**：
  - 语法高亮：`.data`、`.text` 这类分段指令用单独的颜色并带一条底色，而且总是顶格写（在缩进的行里打出来也会自动移到行首）；标签定义和对已定义标签的引用（如 `jal sum`、`bl factorial`）都是粉色。
  - 自动补全的样式仿照 VS Code：行首提示指令（右侧显示说明和全部写法），操作数位置提示寄存器和已定义的标签。MIPS 的寄存器不打 `$` 也行，输入 `t0` 就会提示 `$t0`。Enter 或 Tab 确认。
  - 按 Tab 缩进 4 个空格（制表符也按 4 格显示），示例程序同样缩进 4 格。
  - 输入 `"` `'` `(` `[` `{` 时自动补上另一半，光标停在中间；接着输入另一半会直接跳过去，在两者之间按退格会一起删掉。单词后面的撇号（如注释里的 don't）不会补。
  - **格式化**（macOS 上按 ⇧⌥F，其他系统按 Shift+Alt+F，和 VS Code 一样；也可以点工具栏的“格式化”）会按示例程序的样子排版：分段指令和标签顶格，语句缩进 4 格，助记符补齐到 8 列，逗号后一个空格，数据段排成“标签、伪操作、数值”三列，行尾注释对齐（MIPS 在第 32 列，AArch64 在第 40 列，中文按两格宽计算）。写在指令前面的标签会移到单独一行。格式化只改空白，汇编结果和原来完全一样；按一次撤销就能恢复；如果没有行被移动，暂停中的程序可以接着跑。
  - 点行号设断点；汇编错误直接标在出错的位置；正在执行的那一行高亮。
  - **修饰键点击**：在 macOS 上按住 ⌘（Windows 和 Linux 上是 Ctrl）点一条指令，会在“指令集”栏目里打开这条语句；点标签引用或宏调用，会跳到它的定义。按住修饰键时，可点击的词会像 VS Code 一样加下划线并显示手形指针。定义在被包含文件里的标签没有可跳转的编辑器。
  - “新建”开一个空文件；也可以打开源文件（MIPS 是 `.asm`，AArch64 是 `.s`，或者直接拖进编辑器）、下载，或者从“示例程序”里选一个。新建、打开或换示例时，如果当前代码改过还没保存（下载过、刚打开或刚新建的都算已保存），会先问你：保存（下载）、不保存，还是取消。这时关掉或刷新标签页，浏览器会先问要不要离开（浏览器只在你点过或在页面里打过字之后才会问）。切换界面语言时，示例程序的注释也会跟着换（代码和行号不变，正在运行的程序不受影响）。代码会自动保存在浏览器里。
- **不需要单独汇编**：代码改过之后，点运行、单步、上一步、自动或重置时会先自动重新汇编。比较慢的操作会显示一个转圈的加载动画。
- **三种执行方式**：
  - **单步**：一次执行一行源码。MIPS 的伪指令（如 `li`、`la`、`blt`）展开成的几条真指令一次执行完；工具栏的“单步按”可以改成“真指令”，一次只执行一条真指令（和 MARS 一样），这时会标出“伪指令第 k/N 条”。AArch64 每行就是一条指令，调用一次内置 C 库函数算一步。
  - **运行**：一直执行到结束、断点、需要输入或出错。程序分成约 12 毫秒一段来跑，每段之间让浏览器刷新界面、响应点击，所以长时间运行时页面不会卡住，随时可以暂停。
  - **自动**：按设定的间隔（0–2000 毫秒，运行中可调）一步一步自动执行。
  - **上一步**最多可以撤销 2000 步，寄存器颜色、栈和内存也一起回到当时的状态。
- **终端**：程序输出直接显示在这里，需要输入时在终端里打字。另有“消息”页（汇编和运行时的报错）和“文件”页（程序读写的文件，可以上传和下载）。
- **寄存器**：全部寄存器放在一个面板里，分页显示。**灰色**是还没用到，**绿色**是被读过，**红色**是被改过；上一步改过的寄存器会用更深的红色一直标着，直到执行下一步。点任何一个格子，可以看它的十六进制、二进制、有符号和无符号十进制、字符，浮点寄存器还能看浮点值。
  - MIPS：通用（32 个 + HI/LO）、浮点（`$f0`–`$f31` 和 8 个条件位）、CP0。
  - AArch64：通用（`x0`–`x30`、`sp`，低 32 位就是 `w`）、NZCV 标志位、浮点和向量（`v0`–`v31` 按选定的通道宽度和格式显示，还有 FPCR、FPSR）、SVE（`z0`–`z31`、`p0`–`p15`、FFR）、SME（SVCR、ZA 阵列、ZT0）、系统寄存器。**ZA** 按网格显示：选一种元素宽度，再选一个 tile（如 `za0.s`）或整个阵列，上一步改过的元素标红。
- **栈**：从栈指针往上看栈里的内容（MIPS 每格 4 字节，AArch64 每格 8 字节），默认显示最上面几格，可以展开到栈底，标出栈指针和帧指针的位置。
- **内存**：每个数据标签是一个条目（标签、类型、地址、值），点开看每个元素。紧跟在后面、类型相同又没有标签的行也算这个标签的（`A: .word 1, 2, 3, 4` 下一行 `.word 5, 6, 7, 8`，`A` 就是 8 个字）；其他没有标签的数据按偏移命名，比如 `A+32`。点开的条目可以选“读作”十六进制、文本或各种宽度的数，比如把缓冲区当字符串或数字看；堆块（MIPS 的 `sbrk`；AArch64 的 `malloc`、`brk`、`mmap`）、写到其他地址的数据也会各成一条。刚改过的地方会高亮。
- **机器码视图**：编辑器上方可以切换到汇编结果（地址、机器码、真指令、对应源码），点一行就在“反汇编”栏目里打开它。
- **AArch64 的设置**在工具栏里：SVE 向量长度和 SME 流式向量长度（128 到 2048 位，默认 256 和 512）。按 SVE 的写法写的程序，换什么长度结果都一样；改了设置，程序会重新开始。

快捷键：F5 运行、F6 自动、F7 单步、F8 上一步、F9 暂停、F10 重置、⇧⌥F（Shift+Alt+F）格式化。

### 指令集

从列表里选一条指令（可以按分组筛选，也可以搜索中文或英文说明），或者直接输入一行汇编。下面会显示它的机器码，每个字按位域画出来，标明每段是什么意思。MIPS 的伪指令会列出展开后的每一条真指令。最下面会在真正的模拟器上把这一行跑一遍，显示执行前后读写了哪些寄存器和内存。一行说不清的指令附有参考表：MIPS 的系统调用、CP0 寄存器和异常码、浮点条件位；AArch64 的 Linux 系统调用、C 库函数、条件码、系统寄存器、异常类别，以及 SME 的模式、tile 和向量组。每个伪操作也都有说明。

### 反汇编

每行输入一个机器字（`0x` 十六进制、`0b` 二进制、32 位 0/1 或十进制），可以在行尾写 `@ 地址` 来指定它所在的位置（影响分支目标的计算），得到汇编文本、位域和说明。

## MIPS32

- MARS 4.5 的**全部 155 条真指令**（整数、HI/LO、SPECIAL2、陷阱、CP0、单精度和双精度浮点），以及**全部伪指令写法**，展开方式和 MARS 一致。
- 汇编指令：`.text` `.data` `.ktext` `.kdata` `.word` `.half` `.byte` `.ascii` `.asciiz` `.space` `.align` `.float` `.double` `.globl` `.extern` `.eqv` `.macro`/`.end_macro` `.include` `.set`。
- **全部 39 个系统调用**（1–17、30–36、40–44、50–59）：输入会在终端里等你打字；31/33 会真的发声；32 会真的等待；40–44 的随机数和 MARS 用同一种算法，设了种子结果一样；50–59 弹出对话框。
- 异常：溢出、陷阱、地址不对齐或越界、`break` 等。程序里写了 `.ktext` 异常处理程序就跳到 `0x80000180`，否则终止并给出和 MARS 一样的报错。
- 内存布局和 MARS 默认配置一样：代码段 `0x00400000`、数据段 `0x10010000`、堆 `0x10040000`、`$gp = 0x10008000`、`$sp = 0x7fffeffc`，小端，不启用延迟分支。和 MARS 一样，每个段实际只有 4 MB，把代码段当数据读会触发地址异常。
- 速度：在 Apple M5 上大约每秒 4000 万到 5500 万条指令。

**故意没有做的**：MARS 的工具（MMIO 键盘和显示器、位图显示器等）、延迟分支、紧凑内存布局。

**故意比 MARS 严格的**：MARS 会默默生成出错的程序的地方，这里直接报错：把指令写在 `.data` 里、超过 32 位的整数、超出 16 位范围的分支、没有结束引号的字符串、`.align` 大于 21、`.eqv` 的替换内容里使用宏参数，以及申请会越过 `0x7fffffff` 的 `sbrk`。

## ARMv9-A（AArch64）

- **指令**：Armv9.4-A 的全部强制特性，加上 SVE2.1 和 SME2.1：
  - 整数和位操作，含 CSSC、FlagM、CRC32，以及 MOPS 的内存复制和填充；
  - 所有寻址方式的加载存储、成对加载存储、独占访问、获取/释放（含 LRCPC）和 LSE 原子操作；
  - 分支、条件选择和系统指令；
  - half、single、double、BFloat16 的标量浮点，支持 FPCR 的全部模式（舍入方式、FZ、FZ16、DN、AH、FIZ、NEP、AHP）和 FPSR 的全部标志位；
  - 全部 Neon，含点积、I8MM、FHM、FCMA、RDM、BF16 和 FP16，以及 AES、SHA-1、SHA-256、SHA-512、SHA-3、SM3、SM4 指令；
  - SVE、SVE2 和 SVE2.1：谓词、首次故障和无故障加载、gather 和 scatter、谓词计数器；
  - SME、SME2 和 SME2.1，含 I16I64、F64F64、B16B16、F16F16：流式模式，ZA 阵列和它的 tile、切片、向量组，ZT0 和 LUTI2/LUTI4，外积和多向量指令。
  - 指针认证和 BTI 按“系统没有开启”的行为实现：`paciasp`、`autiasp` 不改变任何东西，`retaa` 就是 `ret`，`bti` 什么也不做。
- **汇编器**：GNU as 语法，按 clang 的读法：注释用 `//`、`/* */` 和行首的 `#`，`;` 分隔同一行的多条语句，立即数前的 `#` 可写可不写，数字局部标签（`1:`、`1b`、`1f`），表达式和 `:lo12:` 等重定位运算符，`adrp` 的页地址，字面量池（`ldr x0, =值`），以及段、数据、对齐、符号、宏（`.macro`、`.rept`、`.irp`）、条件汇编和 `.include` 等伪操作。
- **Linux 进程**：程序定义了 `_start` 就从那里开始；否则由内置的启动代码设好栈、`argc` 和 `argv`，调用 `main`，再用它的返回值退出。`.text` 从 `0x400000` 开始，数据段紧跟在后面，再往后是堆，栈顶在 `0x0000fffffffff000`（8 MB），小端。
- **Linux 系统调用**用 `svc #0`，`x8` 放 Linux 的真实编号：`read` 63、`write` 64、`openat` 56、`close` 57、`lseek` 62、`exit` 93、`exit_group` 94、`brk` 214、`mmap` 222（匿名内存）、`munmap` 215、`getrandom` 278、`clock_gettime` 113、`nanosleep` 101、`getpid` 172、`getppid` 173、`getuid` 174、`gettid` 178。其他编号返回 `-ENOSYS`，并在终端里说明。
- **内置 C 库**：程序自己没定义时，`bl printf` 这类调用直接可用，就像链接了 C 库：`printf`、`sprintf`、`snprintf`、`puts`、`putchar`、`scanf`、`sscanf`、`getchar`、`malloc`、`calloc`、`realloc`、`free`、`exit`、`abort`、`strlen`、`strcmp`、`strncmp`、`strcpy`、`strncpy`、`strcat`、`strchr`、`memcpy`、`memmove`、`memset`、`memcmp`、`atoi`、`atol`、`strtol`、`abs`、`labs`、`rand`、`srand`、`time`。参数按 AAPCS64 传递（可变参数按 Linux 的约定），`printf` 和 `scanf` 处理浮点（`%f %e %g %a`）的结果和 glibc 完全一样，`rand` 给出的也是 glibc 的序列。所以这些程序在真正的 Linux 上用 `gcc` 编译也能跑。
- **异常**：程序里有 `.ktext` 段时，会得到一张 EL1 向量表（标签 `vectors` 处，没有这个标签就用 `.ktext` 的起点）。未定义指令、`brk`、`udf`、数据和指令中止、对齐错误、EL0 访问 EL1 寄存器，都会交给它处理，同时设好 `ESR_EL1`、`ELR_EL1`、`FAR_EL1` 和 `SPSR_EL1`，用 `eret` 返回。没有向量表时，程序像 Linux 进程收到信号（SIGILL、SIGSEGV、SIGBUS、SIGTRAP）那样停下，并给出异常类别、ESR 和出错地址。`svc #0` 总是交给模拟的 Linux 处理。
- **11 个示例程序**：第一个循环、直接用系统调用、printf 的格式、带栈帧的递归、scanf 输入、堆、浮点、Neon 点积、和向量长度无关的 SVE 循环、用 SME 外积做矩阵乘法、在 EL1 处理异常。
- 速度（Apple M5）：整数指令大约每秒 2400 万到 3000 万条，标量浮点大约 1400 万条，Neon 大约 600 万条，SVE 大约 800 万条。SME 的外积慢得多（以外积为主的循环大约每秒 50 万条），因为每条都要更新整个 tile。

**没有做的**：MTE、FP8、LS64、TME、GCS、D128、RME、中断和定时器、地址翻译（地址是平坦的，按区域检查权限）、调试和跟踪、大端模式。

## 开发

需要 Node.js 22.12 以上（Pages 工作流用的是 Node 24）。

```bash
npm install
```

```bash
npm run dev
```

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动开发服务器 |
| `npm test` | 跑全部测试（单元测试，和 MARS、LLVM、CPU 的标准答案比对，AGENTS.md 格式检查） |
| `npm run typecheck` | TypeScript 和 Vue 类型检查 |
| `npm run build` | 生成 `dist/index.html`（单个文件，可以直接双击打开） |
| `npm run preview` | 本地预览构建结果 |
| `npm run golden` | 用 MARS 重新生成 MIPS 的标准答案 |
| `npm run llvm-golden` | 用 clang 和 objdump 重新生成 AArch64 的编码标准答案 |
| `npm run native-golden` | 在 Apple 芯片的 Mac 上重新生成 AArch64 的行为标准答案 |

### 引擎怎么校验

所有标准答案都事先生成好、提交进了仓库，所以跑 `npm test` 不需要 Java、MARS、clang，也不需要特定的 CPU。

- **MIPS 和 MARS 比对**：`tests/golden/programs/` 里的测试程序和全部示例程序，都事先用 MARS 4.5 跑过一遍，结果（机器码、数据段、终端输出、最终寄存器、报错）存在 `tests/golden/expected/`。重新生成需要 Java 和 MARS 4.5 的 jar（不放在仓库里）：

  ```bash
  MARS_JAR=~/.cache/assembly-simulator/Mars4_5.jar npm run golden
  ```

- **AArch64 的编码和 LLVM 比对**：在每种编码里随机取机器字，用 objdump 反汇编，和我们的文本比对；把我们的写法交给 clang 汇编，和我们的机器字比对；整个程序也按段逐字节比对。一共覆盖约 65,000 种编码，另外在整类指令的范围里随机取了 29,000 个字。`npm run llvm-golden` 需要支持 AArch64 的 clang 和 objdump（可以用 `CLANG`、`OBJDUMP` 指定）。
- **AArch64 的行为和真实 CPU 比对**：约 19,000 个单条指令的用例在 Apple M5 上跑过，起始的寄存器、标志位、FPCR 模式和内存都是随机的；我们的模拟器跑完每个用例，寄存器、向量寄存器、标志位、FPSR 和内存都必须一样，出错时也要出同样的错。SVE 和 SME 的用例在 512 位的流式模式下跑，SME 的用例还带上 ZA 和 ZT0。另外还有 5,768 个机器字在流式模式和 ZA 开关的每种组合下都跑过，检查哪种状态禁止哪些指令。`npm run native-golden` 需要装了 clang 的 Apple 芯片 Mac（SVE 和 SME 的用例要有 SME 的芯片，M4 或更新）。
- M5 跑不了的部分（流式模式禁止的 SVE 指令、SM3 和 SM4、MOVT、EL1 异常、系统调用、C 库函数、汇编器报错）用单元测试检查，预期按架构手册的描述来写；`printf` 的格式和本机的 C 库对照。
- **更大范围的对照**：三个生成脚本都可以换种子、换数量（`SEED`、`PER`、`OUT`，LLVM 另有 `COUNT`，MARS 用 `GOLDEN_DIR`），把更大的一批结果写到别处；测试用 `GOLDEN_DIR`、`LLVM_DIR` 或 `NATIVE_DIR` 回放，不动仓库里的标准答案。发布前这样跑过：约 7,000 个 MIPS 程序和 MARS 比对、21 万个 CPU 用例、220 万个机器字和 LLVM 比对、几千个随机程序和 clang 比对，以及各种 FPCR 模式下的 2,450 万个浮点边界用例；发现的问题都已修好，并写进了单元测试。

MARS、LLVM 和 CPU 只用来生成标准答案，网站本身只运行我们自己的引擎。

### 加一种语言的文字

界面上的每一处文字都同时写了中文和英文：组件里用 `t('中文', 'English')`，引擎里用 `L('中文', 'English')` 或 `T('中文', 'English')`。MIPS 真指令的英文说明在 `src/isa/mips/instructions/en.ts`；AArch64 的中英文直接写在每条指令的定义旁边。示例程序的英文版在各架构的 `examples/en/` 里，代码必须和中文版一模一样，只有注释不同（有测试检查；另有测试检查 AArch64 每种编码的说明、反汇编备注和操作数提示都有英文）。

## 部署

`.github/workflows/pages.yml` 会在推送到 `main` 时跑测试、构建，并把 `dist/` 发布到 GitHub Pages。本仓库已经设成 **Settings → Pages → Source = GitHub Actions**；复制到新仓库时同样要设一次。

## 目录

| 位置 | 内容 |
| --- | --- |
| `src/core` | 与架构无关的接口、运行会话、内存、格式化、语言 |
| `src/isa/mips` | MIPS32 引擎：指令表、汇编器、CPU、系统调用、反汇编、示例程序 |
| `src/isa/arm64` | AArch64 引擎：指令表、汇编器、带软件浮点的 CPU、Linux 和 C 库、反汇编、示例程序 |
| `src/ui` | Vue 界面：编辑运行、指令集、反汇编 |
| `tests` | 测试，以及 MARS、LLVM 和 CPU 的标准答案 |
| `scripts` | 生成标准答案的脚本 |

每个文件夹里都有一份英文的 `AGENTS.md`，说明这个文件夹负责什么、有哪些约束、每个文件做什么、进度如何。
